What changed, and what the numbers cannot say.

Two agent changes shipped together; the measurement covers their combined effect.

Changes to the agent

Pre-call route check (prompt 2.3.16). Before pricing, the agent checks that each entry and exit belong to the same road and direction, keeping the places the user asked for. In the October 10 training runs it cut rejected pricing calls from 16 to 8 per run.

Eastern display times (prompt 2.3.17, tool 1.6.0). The pricing tool now supplies ready-to-show New York times such as “5:12 PM EDT”, and the agent copies them. Before the fix, two of three production observed-time answers were four hours early.

20-turn chats, chat persistence across a refresh, and billing alerts also ship in v1.2.0. They sit outside the agent’s prompt and tools, and these runs do not measure them.

Limits of this evidence

The holdout is not blind. Its cases were read on October 10 to diagnose failures and then repaired, and earlier aggregate holdout scores informed the prompt 2.3.16 choice. Treat these results as descriptive, not as unseen-production accuracy.

Frozen tool replay, five runs. Tools replay recorded data rather than live prices. In these runs, single runs of identical code moved by up to 16 points, so five runs per agent cannot confirm a gain of a few points.

The production agent ran holdout and training 5.2.2 because it cannot read tool 1.6.0’s new time fields. Version 5.2.13 adds only those derived strings: cases, routes and prices are identical.

How these numbers were measured

Success: an attempt succeeds only when every required Outcome, Grounding, Rules, and mechanical check passes on a valid scored attempt. Pass³ is the share of cases that succeed on all three attempts, counted directly rather than cubed from the attempt rate. An inconclusive attempt, where the simulated user was invalid, counts as not passed.

Design: old and new runs alternated on one day, five of each with the old agent first in each pair, under the same approved evaluator calibration. Each holdout run covers all 25 cases three times. One training run per agent covers the 50 training cases three times.

Uncertainty: the page reports every run and its range. Only aggregate scores leave the holdout store, so this entry publishes no case-level bootstrap interval.

The production agent: v1.1.2’s prompt and tools ran on the harness commit that introduced 2.5.19. Its prompt, agent and tool code match v1.1.2 byte for byte, except a version label that reads 2.3.16. Earlier holdout runs of the same agent, on October 10 under harness 2.5.18, scored 76%, 60% and 48%.

Provenance: the candidate was measured at commit 532f9fed. Between the measured commit and v1.2.0, only the RDS trust-bundle pin and this scorecard changed; no prompt, tool or agent code. The measurement cost $4.77 across all model roles.

How to read these numbers

Success: all required Outcome, Grounding, Rules, and mechanical checks must pass on a valid scored attempt. Headline success uses all 300 planned slots. The baseline’s one inconclusive receives no success credit; its scored-only rate is 257/299 (86.0%), distinct from the headline 257/300 (85.7%). Nothing was dropped or replaced.

Uncertainty: descriptive 95% percentile intervals use 10,000 bootstrap draws, seed 360, resampling the 99 scenario groups in sorted order. Linked cases and all three attempts stay together. The change interval resamples the same groups across baseline and final, compares their success rates using each draw’s slot count, and does not treat attempt numbers as paired random seeds. The baseline interval is supplemental: its canonical runner interval is null because of the inconclusive. The final success interval matches the recorded runner result.

Consistency and dispersion: cases passing all three attempts are counted directly. Their intervals preserve the same scenario groups and use each draw’s case count. SD is the sample standard deviation of the three repetition success rates, in percentage points. These repetitions share cases and unseeded model sampling; a narrow observed spread is not a guarantee.

What changed: an explicit cancellation instruction stops clarification and pricing after cancellation. Directed entry-to-exit relationships in the location catalog, with selection guidance, help choose direction variants together. The combined candidate’s aggregate gain does not prove which edit caused which change.

Limits: these are exposed development cases under frozen tool replay, after candidate search on the same set. They do not estimate unseen-production accuracy, execute live pricing, or establish production qualification. Recorded grades are preserved, including known grading limitations. The selected search run is subject to selection bias and is not pooled with final verification.

Provenance: final verification evaluated commit 46476e87. It recorded prompt metadata 2.3.14 with the candidate SOP; publication advanced only that version literal to 2.3.15. All 100 rendered prompt hashes, tool schemas, model settings, and measurement inputs matched. The normal development workflow still defaults to one repetition. No holdout was evaluated for this entry.
