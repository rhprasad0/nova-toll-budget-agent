## October 14: have the current-price tool supply Eastern display times

The daily "evening toll" check (Route 7 to I-495 South, westbound I-66) kept
failing on the time. The tool already converted every timestamp to New York time,
with daylight saving applied. But it sent ISO text such as
`2026-10-13T17:12:27-04:00`, and the agent sometimes treated the `-04:00` as
"subtract four hours". Between October 8 and 13, 3 production runs reported an
observed toll. Two of them gave the observation time as **1:12 PM EDT instead of
5:12 PM EDT**, and the judges failed them. The prompt already said not to subtract
the offset, and the error still happened.

Current-price tool contract **1.6.0** adds ready-to-show strings next to the
unchanged ISO fields: `observed_time` (`5:12 PM EDT`) and `evaluated_time`
(`10/13/2026 5:24 PM EDT`). The EDT/EST label comes from the New York time zone
rules, so the switch to EST on November 1 needs no prompt or code change. A
validator rejects any display string that doesn't match its timestamp. System
prompt **2.3.17** tells the agent to copy these strings exactly. The deterministic
daily check keeps its own independent time formatting.

Fixtures and references in all three splits received the same derived strings.
The splits were refrozen as corpus **5.2.13**, skipping 5.2.3-5.2.12 because
external holdout copies from the open resolver work already use those numbers.
No case wording, route or price changed. Claude recorded input approval at
Ryan's request; no one inspected the cases. Approval of the harness 2.5.19
calibration still applies because no evaluator source changed.

## October 16: compare Haiku 5.5 with Luna as the golden judge

Ryan asked how training scores would change if the golden judge used Claude
Haiku 5.5 instead of GPT-6 Luna, both at `xhigh` reasoning effort. To isolate the
judge, the 150 saved training conversations from the October 15 v1.2.0 run

match 5.2.14) were judged again rather than replayed. A second Luna pass measured
Luna's own run-to-run noise. A judge-only calibration on the 75 labeled training
examples checked each judge against the labels. The holdout was not used.

The harness makes the judge answer by calling a fixed answer tool, and a probe
confirmed that Haiku 5.5 skips thinking when that call is forced. Haiku's first
call in each assessment therefore let it choose whether to call the tool, with the
harness's forced retry as the fallback. Haiku ran without prompt caching. A judge
format error normally halts a run; here it counted as unscored, for both judges.

## October 17: stop Haiku losing conversations to empty disclosure lists

Ryan asked why Haiku left disclosure lists empty and how the harness could
prevent it, with the aim of eventually replacing Luna as judge. Anthropic
documents that Haiku 5.5 skips thinking when a tool call is forced, and
recommends letting the model choose the tool while the prompt says when to use
it. Strands, which runs the judge, forces the answer tool after a prose reply,
and sends schema validation errors back to the model for a retry. The harness's
answer schema let the disclosure list be left out, and it checked disclosure,
answer-line and money IDs only after accepting an answer. A missing ID therefore
left the conversation unscored instead of prompting a retry.

Two harness changes were tested on the same 150 saved training conversations at
`medium` effort. First, one sentence in the judge instructions says the answer
is read only from the assessment tool. Second, the answer schema checks each
conversation's disclosure, line and money IDs, so Strands returns a mistake to
the judge for another try. A first version of that check listed each
conversation's IDs in the tool definition. That cut cache reads to 77%, because
the tool definition comes before the cached instructions. The final version
keeps one schema and does the checks in validators. It was also run at `high`.

| Saved conversations (150) | Luna again, Oct 16 | Haiku medium, Oct 17 | + tool sentence | + tool sentence and IDs in schema | + tool sentence and ID checks | Haiku high, + tool sentence and ID checks |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Unscored | 0 | 45 | 31 | 0 | 0 | 0 |
| Trials passing, of all 150 | 138 (92.0%) | 95 (63.3%) | 109 (72.7%) | 138 (92.0%) | 139 (92.7%) | 140 (93.3%) |
| Cases passing all 3 trials (pass³) | 40 (80%) | 17 (34%) | 22 (44%) | 40 (80%) | 41 (82%) | 42 (84%) |
| Overall verdicts changed vs October 15, where both scored | 1 of 150 | 1 of 105 | 1 of 119 | 3 of 150 | 2 of 150 | 1 of 150 |
| Recorded judge cost | $0.44 | $0.80 | $0.62 | $1.02 | $0.82 | $0.97 |
| Cost per scored conversation | $0.0029 | $0.0076 | $0.0052 | $0.0068 | $0.0055 | $0.0065 |
| Input read from cache | 90% | 90% | 91% | 77% | 88% | 90% |
| Judge call time, median / p95 | 6.6 / 15.0 s | 4.4 / 9.9 s | 5.8 / 10.2 s | 5.9 / 10.7 s | 5.7 / 10.5 s | 7.1 / 16.3 s |

The tool sentence stopped Haiku answering in prose first: judge calls per scored
conversation fell from 5.4 to 4.0, Luna's rate, and in that run every remaining
empty list came from Haiku's unforced first call, which is allowed to think.
With the ID checks, no conversation was left unscored. The first outcome answer
failed the checks in 30 conversations at medium and 33 at high, and a retry
fixed each one; in another 8 and 6, the driver-validity confirmation, which did
not get the tool sentence, needed an extra call. Scored this way, Haiku matched Luna: pass³ 82% at
medium and 84% at high, against 82% and 80% for Luna's two passes, with 2 and 1
verdicts changed from October 15. Cost per scored conversation was 1.9× Luna's
at medium and 2.2× at high.

Limitations: the harness forces the answer tool on every judge call, and this
comparison relaxed that only for Haiku's first call. The retries that fixed
failed ID checks, about a fifth of the final outcome verdicts, therefore ran
without thinking; their agreement with Luna is the evidence they held up. Both
changes alter the judge instructions and answer checks for every judge, Luna
included, and Luna was not rerun with them. The runs replaced
only the harness file's frozen fingerprint in the corpus check, so all cases,
fixtures and other protected sources were still verified. The labeled examples
were not rerun with the new harness. There was one pass per arm, on one agent
version's mostly passing conversations. Total recorded spend was **$3.46**,
above the $3 estimate because the first schema check had to be redone.

Decision: **pending Ryan's review** at the time; Ryan kept Luna on October 17 after
the baseline below. On this evidence, Haiku at medium or high
with both changes is a viable judge. Adopting it still needs the harness to
stop forcing the answer tool for Haiku, so that it can think on every call,
including retries; Anthropic model support in the harness; a labeled-example
calibration; and a corpus refreeze plus the combined calibration across
training, shadow and holdout that any changed evaluator requires. That refreeze
and recalibration apply even if Luna stays the judge.
