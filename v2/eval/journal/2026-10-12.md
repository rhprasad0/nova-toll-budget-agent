## October 14: have the current-price tool supply Eastern display times

The daily "evening toll" check (Route 7 to I-495 South, westbound I-66) kept
failing on the time. The tool already converted every timestamp to New York time,
with daylight saving applied. But it sent ISO text such as
`2026-10-13T17:12:27-04:00`, and the agent sometimes treated the `-04:00` as
"subtract four hours". Between October 8 and 13, 3 production runs reported an
observed toll. Two of them gave the observation time as **1:12 PM EDT instead of
5:12 PM EDT**, and the judges failed them. The prompt already said not to subtract
the offset, and the error still happened.

Current-price tool contract **1.6.0** adds ready-to-show strings next to the
unchanged ISO fields: `observed_time` (`5:12 PM EDT`) and `evaluated_time`
(`10/13/2026 5:24 PM EDT`). The EDT/EST label comes from the New York time zone
rules, so the switch to EST on November 1 needs no prompt or code change. A
validator rejects any display string that doesn't match its timestamp. System
prompt **2.3.17** tells the agent to copy these strings exactly. The deterministic
daily check keeps its own independent time formatting.

Training and shadow fixtures and references received the same derived strings and
were refrozen as corpus **5.2.3**. No case wording, route or price changed.
Approval of the harness calibration still applies because no evaluator source
changed. Input approval, the matching holdout refreeze, actor checks and a fresh
baseline are still pending. So are the post-deploy daily runs. No paid evaluation
has run for this change yet.
